# 000153: fix/terminal-delta-followup

## Agent

Antigravity (gemini-3.8-flash) @ triage branch fix/terminal-delta-followup

## Intent

Follow-up hardening and optimizations for terminal delta rendering and session lifecycle after the merge of PR #174:
- Sanitize negative sequence counters and raw byte offsets.
- Suppress terminal emulator responses during delta-append writes.
- Detect daemon log trims under fresh sequence numbers.
- Optimize UTF-8 carry decoding by avoiding redundant list copies.
- Restrict hover popover rebuilds in SessionListTile to visual property changes.
- Ensure coalesced history refreshes are retried via follow-up queue.
- Trim credential tokens at storage read boundaries.
- Add regression unit tests for delta merge edge cases.

## Decisions

- 2026-09-22T22:36-0700: Sanitize sequence numbers and byte offsets with `_sanitizeCounter`. Schema counters are uint64, so negative integers indicate corruption; treating them as unknown (null) prevents corrupt watermarks and safely triggers replay or fallback logic.
- 2026-09-22T22:36-0700: Arm host input suppression during delta append in `_reduceHistory`. Terminal query responses generated by the emulator during delta append must not reach the host. Ensure `_clearSinkState` clears any active suppression timer to prevent leakage across lifecycle boundaries.
- 2026-09-22T22:36-0700: Differentiate daemon log trims from stale snapshots in `isLogShrunk`. When snapshot end bytes are less than current log bytes, classify as a regression requiring replay only if the sequence is fresh (`throughSeq >= lastSnapshotSeq` and `throughSeq >= appliedLiveSeq`).
- 2026-09-22T22:36-0700: Gate popover rebuilds in `SessionListTile.didUpdateWidget` on visual property changes. Include all properties read by the popover builder (`glanceTitle`, `title`, `customLabel`, `subtitle`, `statusColor`, `repoName`, `branch`, `worktreeName`, `cwd`, `snippet`, `snippetDetail`) to prevent stale hover cards while eliminating unnecessary rebuilds.
- 2026-09-22T22:36-0700: Track coalesced history refreshes with `_refreshHistoryFollowUp`. When a history refresh is skipped because a metadata refresh is already in-flight, queue the session ID and trigger the history refresh once the in-flight refresh finishes.
