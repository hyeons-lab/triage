# Devlog: 000170-feat-http-session-history

## Intent
Move session output history transfers off the WebSocket onto a dedicated HTTP endpoint (`GET /api/sessions/{session_id}/history`), restrict the WebSocket to lightweight control RPCs and live event streams, minimize data transferred when loading, resuming, reconnecting, or paging sessions, and ensure native clients work over plain HTTP without SSL/TLS.

## Decisions
- 2026-10-24T22:11-0700 Offload history reads from the session actor thread and WebSocket loop: Add a lightweight non-blocking actor query (`ActorCommand::HistoryCoordinates`) that returns in-memory log coordinates and session metadata in O(1) time, and run segment/journal disk reads plus gzip compression inside `tokio::task::spawn_blocking` in the HTTP handler so neither the PTY actor thread nor the Tokio async worker blocks on disk I/O.
- 2026-10-24T22:11-0700 Single transport-level gzip compression on HTTP: Serve uncompressed `raw_output` and `raw_output_prefix` inside the `THS1` binary history frame and compress the HTTP response once with `Content-Encoding: gzip`, letting browser `fetch` and native `dart:io` `HttpClient` (`autoUncompress = true`) decompress natively in C/C++ off the Dart UI isolate.
- 2026-10-24T22:11-0700 Support tail, forward-delta (`after_byte` + `after_seq`), and backward-page (`before_byte` + `window_bytes`) queries on `GET /api/sessions/{session_id}/history`: Resuming an idle session transfers 0 output bytes; resuming an active session transfers only the delta slice appended since `appliedLogBytes`; paging scrollback up transfers only the older slice prior to `appliedHistoryStart` and splices it onto the client's retained tail.
- 2026-10-24T22:11-0700 Make `AttachSession(history_bytes: Some(1024))` and `SessionEvent::ResyncRequired` metadata-only: Remote clients render from raw bytes via `TerminalStore`, so skipping the 3,500-line `wezterm-term` row walk and raw log read on WebSocket control attaches and lag notifications keeps WebSocket frames small.
- 2026-10-24T22:11-0700 Native cleartext HTTP support without SSL: Configure `NSAppTransportSecurity` (`NSAllowsArbitraryLoads = true`) in `ios/Runner/Info.plist` and `macos/Runner/Info.plist` (matching Android's `usesCleartextTraffic="true"`) and use `dart:io` `HttpClient` over persistent TCP sockets on native targets.

## Issues
- 2026-10-27T14:37-0700 `Test (windows-latest)` failed on `http::history_http_tests::history_http_endpoint_enforces_auth_and_serves_tail_delta_and_backward_pages` (`left: 65, right: 16` at `crates/triaged/src/http.rs:831`): Windows ConPTY wraps console screen updates in VT initialization, window title, and cursor-visibility escape sequences (`65` bytes total instead of `16`), and polling `bytes_logged >= 16` could exit on ConPTY's initial clear-screen sequence. Resolved by waiting for `"0123456789abcdef"` in `visible_rows` with stabilized `bytes_logged` and asserting byte offsets and slices against the captured full `raw_output`.
