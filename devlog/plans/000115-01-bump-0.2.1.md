# 000115-01 bump 0.2.1

## Thinking

0.2.0 is published on crates.io for all five crates, and `v0.2.0` is tagged.
Two commits have landed on `main` since that tag:

- #132, the web terminal paste fix
- #133, the session rail group-drag fix

Both are bug fixes against shipped behaviour, with no API change and no new
surface, so the patch component is the one that moves. Nothing here justifies a
minor bump, and 0.2.0 is taken, so re-publishing it is not an option either.

Version is not edited by hand. `VERSION` is the single source of truth and
`scripts/bump-version.sh` propagates it to `Cargo.toml`
(`[workspace.package].version` plus the internal path-dep pins), `Cargo.lock`,
and the Flutter client's `pubspec.yaml`, preserving the `+1` build number.
`--check` re-verifies that every one of those agrees, and is what CI runs, so
the same command is the local gate.

Publishing is a separate, explicitly authorised step. This branch only moves the
number; it does not push a tag or run `cargo publish`.

## Plan

1. Worktree `chore/bump-0.2.1` from `origin/main`, upstream cleared.
2. `scripts/bump-version.sh 0.2.1`, then read the diff rather than trusting it.
3. `scripts/bump-version.sh --check` to confirm no file drifted.
4. Run the gates CI runs: `cargo fmt --all --check`, `clippy` with `-D warnings`,
   `cargo doc` with `RUSTDOCFLAGS=-D warnings`, and `cargo test --workspace`.
5. Devlog, then commit the bump and the devlog together and push once.
6. Open the PR. Leave the publish itself to a separate, confirmed step.
