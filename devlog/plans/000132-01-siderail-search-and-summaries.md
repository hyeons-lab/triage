# Plan: 000132-01-siderail-search-and-summaries

## Thinking
The user requested two related capabilities:
1. **Siderail Search Feature**: It is currently difficult to locate a particular session in the side rail. We need a search feature that searches across:
   - Repository (`repoRoot`, `repoName`)
   - Current working directory (`cwd`)
   - Worktree (`worktreeRoot`, `worktreeName`, inferred worktree)
   - Session summaries (`snippet`, `snippetDetail`)
   - Session titles and branch names (`title`, `displayTitle`, `railTitle`, `branch`, `sessionId`)
2. **Session Summary Audit & Enhancement**: Audit the session summaries generated by the daemon (`triaged`). Currently they don't have enough information to differentiate or they lose historical context (e.g., collapsing to "idle at shell prompt" when previous work was done). They should always state, if known, the repo and worktree, and the initial/main body of work description.

### Analysis of Siderail Search
- `SessionRail` in `flutter/triage_client/lib/main.dart` renders the sidebar of sessions.
- We should add a search bar in `_buildExpandedRail` with search input, clear button, and placeholder `Search sessions...`.
- Add `sessionMatchesSearch(SessionVm session, String query, [DateTime? now])` in `flutter/triage_client/lib/session_rail_layout.dart` or `main.dart` to perform case-insensitive substring matching on:
  - `repoRoot`, `repoName`
  - `cwd`
  - `worktreeRoot`, `worktreeName`, `_inferredWorktreeRoot`
  - `snippet`, `snippetDetail`
  - `title`, `displayTitle`, `railTitleAt(now)`, `branch`, `_inferredBranch`, `sessionId`
- Filter the displayed sessions and group headers accordingly in `buildRailItems`.
- Handle edge cases:
  - Empty search results state ("No matching sessions").
  - Clear button to reset search.
  - Correct original session selection index when tapping filtered results.
  - Disable reorder drag gestures while search is filtered.

### Analysis of Session Summary Audit & Generation
- In `crates/triaged/src/summarizer.rs`:
  - `build_prompt_text`: Previously took only the last 20 visible lines (`kept[start..]`), discarding initial session output and commands. If a session ran a large command and settled at a prompt, or output scrolled, historical context was lost. We should preserve both the initial output (first ~8-10 non-empty lines showing task launch/command) AND the latest activity lines (last ~16-20 lines showing current status).
  - `SYSTEM_PROMPT` & `DETAIL_SYSTEM_PROMPT`: Update instructions to explicitly require identifying and describing the initial/main body of work description along with the current state, and preserving work history rather than collapsing into generic idle descriptions.
  - Header formatting in `generate_detail`: Ensure repo and worktree (via `localization_label`, and falling back to cwd when outside git) are always included at the top of the detail summary.
- In `crates/triaged/src/session.rs`:
  - Ensure `SummarizeJob` carries context and cwd so `generate_detail` can properly localize the session.

## Plan
1. **Rust Daemon (`triaged` / `triage-core`)**:
   - Update `build_prompt_text` in `crates/triaged/src/summarizer.rs` to retain both initial session context/command lines and recent activity.
   - Update `SYSTEM_PROMPT` and `DETAIL_SYSTEM_PROMPT` in `crates/triaged/src/summarizer.rs` to prioritize the initial/main body of work description and current status without losing history.
   - Update `generate_detail` in `crates/triaged/src/summarizer.rs` to ensure repo/worktree/cwd are always stated in the header if known.
   - Add/update Rust tests in `crates/triaged/src/summarizer.rs` and `crates/triage-core`.

   - Add unit and widget tests in `flutter/triage_client/test/`.
