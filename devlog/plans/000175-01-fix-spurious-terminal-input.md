# 000175-01: Fix Spurious Terminal Input in Normal Shell Sessions

## Thinking

Inspection of `session-303/segment-000001.tlog` on a live `zsh` session where random characters (`>|Triage 0.3.0`, `65;4;6;18;22;52c`, `2026;2$y`, `20;10t`, `1016;2$y`, `0;61;459M0;61;459m`, and `35;55;29M35;54;29M...`) were inserted into the shell command line identified three distinct root causes:

1. **Daemon handover replays historical terminal queries into the live PTY (`spawn_adopted_pty_runtime` in `crates/triaged/src/session.rs`)**:
   - Unlike `LogInitialization::ReplayExisting` and `OutputState::reflow_from_log`, which gate `wezterm_term::Terminal` with `replay_gated_pty_writer()` while replaying historical log bytes and only attach the live PTY writer after draining `ThreadedWriter`'s reply queue, `spawn_adopted_pty_runtime` constructed `terminal` with the live PTY writer *before* calling `output.replay_tail(replay_len, &replay)`.
   - Consequently, every `triaged reload` (zero-downtime handover) replayed up to 16 MiB of historical `.tlog` output through `wezterm_term::Terminal` with the live PTY writer attached, causing `wezterm_term` to answer every historical query (`\x1b[>q` XTVERSION, `\x1b[c` DA1, `\x1b[16t` XTWINOPS cell size, `\x1b[?2026$p` and `\x1b[?1016$p` DECRQM) directly into the live shell's stdin.

2. **Stale mouse-tracking modes (`?1000h`, `?1002h`, `?1003h`, `?1006h`) left enabled after a child TUI/agent exits back to an interactive shell**:
   - In `session-303`, Claude Code enabled mouse tracking (`\x1b[?1000h\x1b[?1002h\x1b[?1003h\x1b[?1006h`) on the normal screen buffer and exited back to `zsh` without emitting `\x1b[?1000l\x1b[?1002l\x1b[?1003l\x1b[?1006l`.
   - Because `?1003h` (any-event mouse motion tracking) and `?1006h` (SGR mouse encoding) remained latched in the session's terminal state and replayed history log:
     - Moving the mouse cursor over the web terminal (`xterm.js`) emitted a stream of SGR motion sequences (`\x1b[<35;55;29M\x1b[<35;54;29M...`), which `zsh` echoed into the command line as `35;55;29M35;54;29M...` while also triggering `term.scrollToBottom()` and bumping `last_input_ms`.
     - Clicking the native Flutter terminal (`xterm.dart` in `terminal_pane_stub.dart`, where `TerminalController` defaulted to `PointerInputs({PointerInput.tap})`) called `renderTerminal.mouseEvent`, which used `getCellOffset` (including scrollback offset `459`) to emit `\x1b[<0;61;459M\x1b[<0;61;459m` into `zsh`.
   - When the session's root process is an interactive shell (`is_interactive_shell_launch`) and the root shell itself is the PTY's foreground process group (`pty_foreground_pgid(fd) == Some(root_pid)`), or when a shell prompt marker arrives on the normal screen without enabling mouse tracking, any active mouse grab (`output.terminal.is_mouse_grabbed()`) is stale state left behind by an exited child process. Synthesizing `MOUSE_TRACKING_RESET_BYTES` (`\x1b[?1000l\x1b[?1002l\x1b[?1003l\x1b[?1006l\x1b[?1005l\x1b[?1015l`) into the session output and dropping mouse report input sequences in `ActorState::write_input` when `!output.terminal.is_mouse_grabbed()` heals both existing sessions on reload and future child exits automatically.

3. **Client-side query response and mouse report handling (`emulator_query_response.dart`, `terminal_pane_stub.dart`, `terminal_pane_web.dart`)**:
   - `isEmulatorQueryResponse` did not match `CSI 6 ; h ; w t` (XTWINOPS cell size report), `OSC 4` / `OSC 12` color reports, or DCS query replies (`\x1bP>|...\x1b\\` XTVERSION, `\x1bP!|...\x1b\\` DA3, `\x1bP[01]$r...\x1b\\` DECRQSS, `\x1bP[01]+r...\x1b\\` XTGETTCAP).
   - Both `terminal_pane_stub.dart` and `terminal_pane_web.dart` called `sendInput(data)` when `isEmulatorQueryResponse(data)` was true instead of dropping the synthetic response immediately.
   - `terminal_pane_stub.dart` constructed `xt.TerminalController()` with the default `PointerInputs({PointerInput.tap})`, causing `xterm.dart` to emit broken scrollback-offset mouse tap sequences on click.
   - `terminal_pane_web.dart` treated SGR/X10 mouse report sequences in `onData` as keyboard input, calling `term.scrollToBottom()`, clearing `_sessionSavedViewportY`, and disarming sticky Ctrl on mouse movement.

## Plan

1. **Daemon (`crates/triaged/src/session.rs`)**:
   - Update `spawn_adopted_pty_runtime` to construct `terminal` with `replay_gated_pty_writer()`, drain replay replies via `output.terminal.advance_bytes(b"\x1b[c")` and `replay_gate.wait_for_dropped_activity_quiet_after(...)` when `replay_len > 0`, and only then call `replay_gate.enable(master.take_writer()?)`.
   - Add `MOUSE_TRACKING_RESET_BYTES` (`b"\x1b[?1000l\x1b[?1002l\x1b[?1003l\x1b[?1006l\x1b[?1005l\x1b[?1015l"`) and reset stale mouse tracking (`output.terminal.is_mouse_grabbed()`) when an interactive shell session is at its root shell (`foreground_pgid == Some(root_pid)`) during handover adoption (`spawn_adopted_pty_runtime`), session restore (`LogInitialization::ReplayExisting`), live output (`ActorState::handle_output`), idle polling (`ActorState::refresh_idle_cwd`), and input (`ActorState::write_input`).
   - In `ActorState::write_input`, detect terminal mouse report sequences (`is_mouse_report_sequence`): drop them if `!self.output.terminal.is_mouse_grabbed()` (after resetting stale mouse tracking if at the root shell), and avoid stamping `self.last_input_ms` for pure hover/motion mouse reports (`is_mouse_motion_only_sequence`).
   - Add unit tests in `crates/triaged/src/session.rs` covering handover adoption query gating, stale mouse-tracking reset when returning to the shell, and dropping mouse input reports when mouse tracking is inactive.

2. **Flutter Client (`flutter/triage_client/`)**:
   - In `lib/terminal/emulator_query_response.dart`, expand `isEmulatorQueryResponse` to cover `CSI 6;h;wt` cell-size reports, `OSC 4` / `OSC 12` color reports, and DCS query responses (`XTVERSION`, `DA3`, `DECRQSS`, `XTGETTCAP`), and add `isTerminalMouseReport`.
   - In `lib/widgets/terminal_pane_stub.dart`, initialize `_xtermController` with `pointerInputs: const xt.PointerInputs.none()` and drop `isEmulatorQueryResponse(data)` in `_onTerminalOutput` without calling `sendInput`.
   - In `lib/widgets/terminal_pane_web.dart`, drop `isEmulatorQueryResponse(data)` in `onDataCallback` without calling `sendInput`, and forward `isTerminalMouseReport(data)` directly without calling `scrollToBottom()`, clearing `_sessionSavedViewportY`, or disarming `_sessionCtrlArmed`.
   - Add unit tests in `test/terminal/emulator_query_response_test.dart`.

3. **Overlapping / Overwritten Upper Lines During Text Output (`terminal_store.dart`, `main.dart`, `terminal_pane_stub.dart`, `crates/triaged/src/session.rs`)**:
   - **Emulate `CSI Ps Z` (`CBT`, Cursor Backward Tabulation) and `CSI Ps I` (`CHT`, Cursor Forward Tabulation) for native `package:xterm` (`writeToXterm` in `terminal_store.dart` and `SessionVm` in `main.dart`)**: `package:xterm`'s parser has no handler for `Z` or `I`. Modern TUIs (`agy`, `claude`, `codex`) emit `\x1b[3Z` / `\x1b[7Z` after status-bar updates and multi-line cursor movements to step backward by 8-column tab stops. Ignoring `CBT` leaves the cursor near the right margin so typed or streamed text wraps onto extra rows, causing subsequent `\x1b[NA` upward cursor jumps to land mid-block and overwrite earlier text at the top of the block.
   - **Strip Kitty keyboard protocol `CSI u` sequences (`\x1b[?u`, `\x1b[>1u`, `\x1b[<1u`, `\x1b[<u`, `\x1b[=1u`, `\x1b[1u`) in `TerminalStore._stripUnsupportedPrivateCsi`**: `package:xterm` maps `CSI u` to `restoreCursor()` without checking private prefixes (`?`, `>`, `<`, `=`) or parameters, jumping the cursor to `(0, 0)` (top of the viewport) whenever a TUI pushes, pops, or queries Kitty keyboard flags.
   - **Preserve consecutive bare LFs before relative horizontal cursor movements (`\n\n\x1b[24D`, `\n\x1b[3Z`) in `TerminalStore` and `crates/triaged/src/session.rs`**: Skip contiguous `0x0A` (`\n`) runs before checking for `CSI <digits> C/D/Z` and carry back the entire bare-LF run when a trailing escape prefix splits across chunk boundaries.
   - **Reclaim cross-device PTY size drift on native desktop and local interaction (`main.dart`, `terminal_pane_stub.dart`)**: Allow `_selectedSessionGridDriftedFromHost()` and `_onSessionViewFit` to reconcile host PTY size on native platforms as well as web, trigger `_refitActiveSession()` when typing into the active foreground session while `hostSizeDriftedFromOwnFit || _selectedSessionGridDriftedFromHost()` is true, and clear `_sessionLastResizeOutCols`/`Rows` on `_onRefit` in `terminal_pane_stub.dart`.

5. **Scrollback Layout and Refit Above Viewable Area (`crates/triaged/src/scrollback.rs`, `crates/triaged/src/session.rs`, `flutter/triage_client/lib/main.dart`, `flutter/triage_client/lib/widgets/terminal_pane_stub.dart`, `flutter/triage_client/test/widget_test.dart`)**:
   - **Resize native `SessionVm.terminal` before `HistoryBytes` replay (`SessionVm._flushPendingHistory` in `main.dart`)**: `TerminalControllerSink.resize(cols, rows)` is a no-op because views own sizing, and `_loadDaemonSessionInto` creates a fresh `SessionVm` (with default `80x24` `xt.Terminal`) and calls `session.noteViewFit(cols, rows)` inside `setState` before `TerminalView` has built or laid out. As a result, `rawOutputPrefix` + `rawOutput` were written into `session.terminal` while it was still `80x24`, wrapping lines at 80 columns and executing wide-grid cursor movements on an 80-column grid before `TerminalView` resized `session.terminal` on the next frame. Calling `terminal.resize(_viewCols, _viewRows)` in `_flushPendingHistory()` before dispatching `HistoryBytes` ensures all content above the viewable area is emulated at the true fitted terminal dimensions from byte 0.
   - **Make Refit (`_refitActiveSession` / `_replayHistoryForRefit` in `main.dart`) re-layout content above the viewable area**: `_refitActiveSession` previously only jiggled `resizeSession(cols, rows - 1)` -> `resizeSession(cols, rows)`, which sends `SIGWINCH` so the foreground child redraws the visible viewport, leaving scrollback above the viewable area untouched. Update `_refitActiveSession` to re-fetch the session's held history window via `attachSession` and replay it (`session.applyHistory(..., preservePendingLive: true)`) at the fitted `(cols, rows)` before the `SIGWINCH` jiggle redraws the visible area, while preserving the user's distance from bottom in `terminal_pane_stub.dart` (`_refitSavedDistanceFromBottom`) if scrolled up.
   - **Track `_lastWorkspaceFittedSize` on native (`TerminalPane.getLastFittedWorkspaceSize` in `terminal_pane_stub.dart`)**: Record `_lastWorkspaceFittedSize = (height, width)` in `_onTerminalResize` and return it from `TerminalPane.getLastFittedWorkspaceSize()` so switching to a session on native uses the workspace's actual fitted grid size instead of falling back to `_estimatedTerminalRestoreSize`.
   - **Preserve resized session dimensions across handover and heal stale scrollback journals (`crates/triaged/src/session.rs`, `crates/triaged/src/scrollback.rs`)**: Update `launch.size` in `resize_session`, include `size: self.size.clone()` in `ExtractedHandover` / `serialize_active_sessions`, query the live kernel PTY window size (`TIOCGWINSZ`) in `spawn_adopted_pty_runtime`, and rebuild the scrollback journal (`replay_tail_with_scrollback_rebuild`) when `adopted_size != h_sess.size`. In `scrollback::encode_line` and `OutputState::journal_scrolled_lines`, omit hard `\r\n` on soft-wrapped rows (`line.last_cell_was_wrapped()`) and coalesce consecutive soft-wrapped rows into a single logical-line journal record so journaled scrollback reflows cleanly to any client width.

6. **Follow-Up: Split-History Seam, Mode 2026 Spinner Trimming, and Viewport Separation (`crates/triaged/src/scrollback.rs`, `crates/triaged/src/session.rs`, `flutter/triage_client/lib/terminal/terminal_intent.dart`, `flutter/triage_client/lib/terminal/terminal_store.dart`, `flutter/triage_client/lib/services/triage_websocket_client.dart`, `flutter/triage_client/lib/main.dart`)**:
   - **Ignore `\n` inside Mode 2026 synchronized update blocks in `trimHistoryTailWithOffset` (`terminal_store.dart`)**: Live TUI sessions emit thousands of bare `\n` bytes inside `\x1b[?2026h ... \x1b[?2026l` status/spinner frames in the 32 KB `raw_output` tail. Counting those `\n` bytes toward `maxLines` (1,000) exhausted the line budget inside `raw_output`, dropping 100% of `rawOutputPrefix` and cutting `raw_output` mid-spinner-frame. Skip `\n` counting while inside Mode 2026 blocks and advance any cut that lands inside a Mode 2026 block past the closing `\x1b[?2026l`.
   - **Eliminate the `rows - 1` seam gap and cursor-addressed viewport overwrite on split history (`session.rs`, `triage_websocket_client.dart`, `terminal_intent.dart`, `terminal_store.dart`, `main.dart`)**: Because `ScrollbackJournal` stamps each line with `bytes_logged` when it scrolls off row 0, lines on rows `0 .. rows - 2` at `seam` only scroll off during `(seam .. logged_tail_bytes]`. In `overlay_raw_output_history`, serve `probe` (`<= logged_tail_bytes`) when `!prefix.is_empty()` so zero scrolled lines are omitted at the seam. In the client, encode `styled_rows` + `cursor` into `rawOutputViewport` wrapped in `\x1b[?7l ... \x1b[?7h` (`rawOutputViewportFromSnapshot`) and replay `[...trimmedPrefix.bytes, ...rawOutputViewport]` when both `rawOutputPrefix` and `rawOutputViewport` are non-empty so `raw_output_prefix` pushes 100% of its lines into scrollback above row 0 and the visible viewport is painted without cursor-addressed `raw_output` overwriting the bottom `rows - 1` lines of scrollback.
   - **Revert soft-wrap `\r\n` omission and handover `.slog` rebuilds (`scrollback.rs`, `session.rs`)**: Omitting `\r\n` on soft-wrapped lines in `encode_line` glued adjacent full-width table/box rows together on wider viewports, and `replay_tail_with_scrollback_rebuild` re-emulated multi-width historical `.tlog`s at a single `TIOCGWINSZ` width, wrapping wide alternate-screen cursor jumps into synthetic `.slog` garbage. Restore per-row `\r\n` with trailing default-styled space trimming in `encode_line` and keep `ScrollbackJournal` strictly append-only during live ingest.
